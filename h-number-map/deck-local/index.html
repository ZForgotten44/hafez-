Scope

Four things came out of one drawing

H-number system

One running number per lot, H000001 to H003185, with one formula that maps the old label to it.

Atlas

One HTML file: lot map, search, layers, one-page section PDFs.

Explainer

Page that walks through the old numbering, the new one and the formula.

3D model

three.js scene fitted to the lot map and the aerial photo.

Stack

Python (PyMuPDF, OpenCV, NumPy, SciPy, Shapely) does the extraction and image work. The output is static HTML and JavaScript. The 3D view is three.js r128. No server.

How the H-numbers were built · 6

lots.py

Finding lot cells on a raster

1. Draw only the lot-colour lines onto a blank image at 8 px per drawing unit.

2. Label the empty space as connected regions. An enclosed region is one lot cell. The big outside region is thrown away.

3. Trace each region's boundary and divide by 8 to get a vector outline.

Why not join the vector strokes directly: they are separate lines that stop a little short of each other, so polygon building leaves gaps. On the raster a 1–2 px gap closes when the lines are drawn thick enough.

# simplified from lots.py

S = 8

img = np.zeros((H*S, W*S), np.uint8)

for p in lot_colour_paths:

cv2.polylines(img, [p*S], False, 255, 2)

n, lab = cv2.connectedComponents(img == 0)

for k in range(1, n):

if touches_border(lab == k): continue

c = cv2.findContours(lab == k, ...)

cells.append(c / S)

fit.py

Sizing 3,000 labels to fit their lots

Where: the pole of inaccessibility of the outline (polylabel). It is the point farthest from every edge, so it sits inside thin and curved lots too.

How big: the largest font size whose measured text box fits inside the outline pulled in by a margin.

Measured, not guessed: the monospace advance is 0.60 em and the ink is at most 0.77 em tall. Both were measured in Chromium.

On the page: each label has a fixed text length so it looks the same in every browser.

# sketch, per lot

cx, cy = polylabel(outline)

inner = outline.buffer(-margin)

for size in sizes_desc:

w = 0.60 * size * len(text)

h = 0.77 * size

if inner.contains(box(cx, cy, w, h)):

break

How the H-numbers were built · 12

Part 2 · Decoder to formula · step 1

The old code is a lookup table per section

Section B is 22 columns by 19 rows. The decoder builds a dictionary from every legacy label to a (column, row) cell.

The H-number is then the position of that cell along the sweep: 44 × (row − 1) + column.

extract_decoder.py dumped all of these builders. The job was to replace each table with arithmetic that gives the same answer.

# s4decoder1.py

def build_B_decoder():

d = {}

for r in range(1, ROWS+1):

d[f"{20*r}H"] = (1, r)

d["19A"] = (2, 1)

for r in range(2, ROWS+1):

d[str(19 + 20*(r-1))] = (2, r)

for r in range(1, ROWS+1):

for c in range(3, 22):

d[str((r-1)*20 + (22-c))] = (c, r)

for r in range(1, ROWS+1):

d[str(12 + 19*(r-1))] = (22, r)

return d

How the H-numbers were built · 15

Step 4 · hformula.py

One formula shape for every section

H = O + Σ + σ·W + κ

O

Lots already swept before this pass: 836, 1871, 2331 and so on.

Σ

Lots in all earlier rows of both sections of the pass.

σ·W

If the lot is in the second section of the pair, the first section's width in this row. σ is 0 or 1.

κ

Place of the lot inside its own row, from the old label.

def pre(w1, w2, r):

return sum((w1[j] if j < len(w1) else 0) + (w2[j] if j < len(w2) else 0) for j in range(r - 1))

Step 5 · gen_giant.py

Compiled into a single JavaScript function

gen_giant.py reads the Python constants and writes one function H(S, L): section letter and old label in, H-number out.

Row widths, twin lists and blocks are written into the file as literals. It needs no other file.

Worked example · section C, label 89

C-89 to H001059, term by term

5

Row (level): the first entry of CT = [19, 38, 57, 76, 95, …] that is ≥ 89 is 95, the fifth.

836

O: C belongs to pass 2, and pass 1 (B, A) already swept 836 lots.

194

Σ: P2[5 − 1] = lots of D and C in rows 1 to 4.

22

σ·W: C comes after D in each row, so add D's width in row 5, WD[4] = 22.

7

κ: CT[4] − n + 1 = 95 − 89 + 1 = 7. No twin lots in this row lie before 89.

836 + 194 + 22 + 7 = 1,059 → H001059

build_pdf.py

Old section B sheet

Each section is rendered from the same geometry as the website, so the label positions are identical.

The script picks the smallest sheet that keeps numbers at 3 pt per map unit or more, otherwise tabloid at the best fit.

How the H-numbers were built · 23

qa.py

Four checks on the placed labels

A · Model

Each label box lies inside its own lot with clearance, clear of every drawn lot line, and overlaps no other number.

B · Outline

Traced lot outlines coincide with the lot lines in the drawing.

C · Browser pixels

Labels and lot lines are rendered separately in a real browser. Count label pixels that touch a line pixel.

D · PDF pixels

The same pixel test on the rasterised PDF pages.

Check C exists because the model cannot see font differences: a font that renders slightly wider than its measured width passes A and fails C.

Screenshots have no coordinates

Inputs: a top-down and a wide Google Earth view, 1500 × 868 each. No geodata, so they have to be aligned to the lot map by image processing.

How the H-numbers were built · 27

Registration · feature matching

Chaining the second view with SIFT

SIFT with 6000 features, ratio test 0.75: 1,319 good matches. RANSAC with a 4.0 px threshold keeps 1,217 inliers. Every 14th inlier is drawn.

The homography between the views is chained with the six-point one: H = G · H1. The wide view lands on the lot map without more clicking.

How the H-numbers were built · 28

Registration · the test

Lot polygons over the warped photo

Warp: 1.4 px per map unit, region (220, 60) to (1800, 1040). The texture is 2212 × 1372.

The check is visual and direct: draw all 3,102 lot polygons on the warped photo and look for drift.

The centre fits. The west edge fits worse (inset in the image), which is the limit of a single homography over the whole area.

Tree detection · attempt 1

Colour mask: rejected

First idea: trees are green. Threshold in HSV: H 28–48, S > 55, V > 95.

It selects patches of bright lawn, not trees. In this imagery the canopies are dark, not green, so a colour range is the wrong tool.

Crop of the map, x 900–1250, y 540–800.

lo = (28, 55, 95); hi = (48, 255, 255)
mask = cv2.inRange(hsv, lo, hi)

How the H-numbers were built · 31

Tree detection · step 2

Dark-blob mask

1. Blur the brightness channel (Gaussian, sigma 2.5).

2. Keep pixels with V < 92.

3. Remove everything known not to be a tree: white map labels, roads, buildings.

4. Morphological opening, 7 × 7, to drop thin shadows and grave lines.

Vb = cv2.GaussianBlur(V, (0,0), 2.5)
dark = (Vb < 92) & ~labels & ~road & ~bldg
dark = cv2.morphologyEx(dark, MORPH_OPEN, k7)

How the H-numbers were built · 32

Tree detection · step 3

One tree per distance-transform peak

A blob can hold several overlapping canopies. The distance transform gives each pixel its distance to the blob edge, and each tree centre is a local maximum of it.

Peak = local max in a 15 × 15 window. Keep it if the distance is at least 10 px, which is the tree's radius in pixels.

In this crop: 150 peaks found, 39 kept. Red = kept, grey = rejected as too small.

dt = cv2.distanceTransform(dark, DIST_L2, 5)
peak = (dt == cv2.dilate(dt, k15)) & (dt >= 10)

How the H-numbers were built · 33

Tree detection · result

415 trees over the whole map

408 leafy (includes the west woods fill, spacing 19) and 7 evergreen. Evergreen if mean V under 58.

Crown radius = r / 1.4 × 1.25, converted from pixels to map units.

Overlaps removed by non-maximum suppression at 0.9 × the larger radius.

Trees within 8 + 0.8 r of a building are dropped. Those were roof shadows.

Keeping 3,000 lots and 2,800 stones fast
