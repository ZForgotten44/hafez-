How the old lot numbers worked, why they were hard to use, and the math that replaces them

This page starts from the raw maps, shows how legacy lot labels behave across the cemetery, and then rebuilds the H-number system as arithmetic you can change and test. Every number on this page comes from the project decoder, and the final formula was checked against all 3,199 lot labels the decoder accepts.

4 · The H-number idea

Instead of naming lots by what is written on them, number them by where they fall along one fixed path through the cemetery. The first lot on the path is H000001, the next is H000002, and so on to H003185. Graves inside a lot get one more digit.

The three rules

  1. The path visits the cemetery in six stretches (called passes below), one after another, each one starting where the last stopped.
  2. Inside a stretch, it goes level by level, and within a level it walks the lots in a fixed order.
  3. A lot's H-number is how many lots the path has already visited, plus one.
Hlot=O+∑j<rWj+k

O lots visited before this stretch, Wj number of lots on level j of the stretch, r the level of this lot, k its place on that level.

Graves

Hgrave=10×Hlot+g

Grave 1 is the top grave of the lot and g runs from 1 to 9. Lot H000001 has graves H0000011, H0000012 and so on. Double-row lots keep their A or B between the lot and the grave digit, as in H001698A3.

The six stretches

Where two sections share a stretch, their levels are woven together: level 1 of the first section, level 1 of the second, then level 2 of each, and so on. That is why one section's H-numbers are not a single block.

5 · The math, step by step

Each block below is a piece of the real system. Change the numbers and watch the H-numbers move.

Step 1 · The two-section sweep (B and A)

Sections B and A each have N columns and share R levels. The sweep takes one level at a time. Constants follow from N and R:

SWEEP = NB + NA
OFFSET = SWEEP × R
H(B, level r, column c) = SWEEP × (r − 1) + c
H(A, level r, column c) = SWEEP × (r − 1) + NB + c

Hover over the grid to read a lot. The reference PDF and the decoder docstring describe the order as "B column 1, A column 1, B column 2 and so on", but the formulas and the code number a whole level of B first and then the same level of A. Flip the switch above to see how that choice moves every H-number after the first lot.

Step 2 · Why the old label is harder than the H-number

H comes from a position. The old label has to be turned into a position first. Section A is the clean example: every row has 19 labels, counted right to left, with three H-lots slipped in. Change the rules and see the labels and their H-numbers.

row r = ⌈ n / step ⌉ place q = n − step × (r − 1)
column c = (N − 2 − q) + [q ≤ t₁] + [q ≤ t₂] + … H-lot: one column earlier
H(A, n) = SWEEP × (r − 1) + NB + c

Section B, where the column rules disagree

B's reference formulas give column 2 the label 19 + 20(r − 1), but column 3 (the first body column) also gets 19 + 20(r − 1). Its last column steps by 19 while the body steps by 20. The decoder resolves a repeated label by letting the later rule overwrite the earlier one.

Step 3 · Rows of different widths (sections D and C)

In D and C the rows are not all the same length, so a fixed SWEEP no longer works. Instead the offset of a level is the running total of all earlier rows:

H(D, row r, place k) = 836 + Σj<r (WD(j) + WC(j)) + k
H(C, row r, place k) = 836 + Σj<r (WD(j) + WC(j)) + WD(r) + k

Edit any width in the table: one extra lot in row 5 moves every later lot by one. The older reference sheet assumed every row had 22 lots and ended with lot C-417 at H001672. The real rows are uneven, which is why the decoder now ends C-417 at H001871.

Step 4 · Twins and trios inside a row (Section C)

Many rows also contain an H-lot next to a plain lot with the same number, and some rows start with an A, B, C trio. Each twin or trio lot pushes everything after it one place along.

k(plain lot n) = (top − n) + 1 + 3·[trio row] + #{ twins t : t > n, or t = n with its H-lot first }
k(H-lot t) = k(plain t) − 1 (H-lot first) or k(plain t) + 1 (H-lot after)

Step 5 · Straight-line sections (M, J, I, L)

Where a section was numbered straight through, H is the lot number plus a constant. Enter a lot to see it:

H(J, n) = 2950 + n (n = 1 … 132)
H(I, n) = 3082 + n (n = 1 … 64)
H(L, n) = 3146 + (n − 68) (n = 69 … 107)
H(M, n) = n + 2556 (n = 82 … 279; the first 51 lots of M are listed)
H(F, n) = n + 2203 for the margin lots 199 … 210

Reverse: H-number to old label

Reverse lookup runs the formula over every known label and keeps the matches; one H-number can have several names (a double-row lot answers to nA, nB and n).

The formula, typeset

H(S,ℓ)=Op(S)+∑j<r(Wj1+Wj2)+σS⋅Wr1+κS(ℓ)

S the section, ℓ the label. Op the lots in all earlier passes (0, 836, 1871, 2331, 2586, 2835). W¹, W² row widths of the first and second section of the pass. σS is 1 for the second section of a pass, else 0. κS(ℓ) is the lot's place on its row. The table below gives κ for each section.
